# 能力、CLI与可靠性边界

当前用途、安装和数据边界以[README](../README.md)为准。本文补充已有CLI，不分发真实采集资料。

## 模块职责

平台SDK统一请求、鉴权、签名、节流、分页停滞检测、视频/分P身份、字幕和收藏写入；Library维护本地标注、备份与恢复；Runtime维护可信插件动作和任务；扩展只控制用户绑定的标签页。上游研究不是产品运行依赖。

## 从现有资料准备分类

snapshot/prepare-cache可只读消费已有摄入SQLite的canonical_document、source_membership、source_registry以及正文/Raw文件；输入路径必须由用户显式提供，不包含该资料库，也不依赖相邻私有项目。snapshot另需自己的B站会话，prepare-cache只使用本地存量资料，不能据此确认实时收藏关系。

```powershell
uv run --no-dev bili-platform --workspace private/review --cookie-file private/credentials/session.json snapshot --folder 待整理 --limit 20 --ingestion-db private/ingestion.sqlite --corpus private/corpus --raw-root private/raw --fetch-subtitles
uv run --no-dev bili-platform --workspace private/review preview --dataset private/review/dataset.json
uv run --no-dev bili-platform --workspace private/review prepare-session --dataset private/review/dataset.json --session-ref local-review --max-chars 6000
uv run --no-dev bili-platform --workspace private/review accept-session --dataset private/review/dataset.json --packet private/review/session-packet.json --decisions private/review/session-decisions.json
```

无已有摄入库时，收藏管理与工作台导入照常可用，不必为了运行本产品建设其他资料系统。`--limit 0` 表示全量；有限批次不承诺完整收藏夹覆盖。prepare-session仅导出可靠证据，不会启动模型；accept-session核对工作集、缓存、精确引文与判断字段。

## 可选模型API

先把examples/provider.example.json复制到private后配置自己的服务、模型和环境变量；示例域名不可用，避免意外发送资料。

```powershell
uv run --no-dev bili-platform --workspace private/review budget --dataset private/review/dataset.json --provider-config private/provider.json --max-chars 6000 --max-output 600 --summary
uv run --no-dev bili-platform --workspace private/review classify --dataset private/review/dataset.json --provider-config private/provider.json --allow-live --input-cap 100000 --output-cap 600 --max-chars 6000 --max-output 600
```

上面的数字只是命令参数示例，不是推荐费用或足够覆盖全部视频的承诺。先检查budget的实际资料范围，再选择本次上限。输入包括BVID、标题、限定简介、字幕片段与ID，不发送B站Cookie、配对令牌或私人备注；输出受结构和引文校验。未取得用量时记录未知，不写成零成本。模型响应损坏或预算不足不会偷偷换用标题判断。

## 收藏执行与恢复

工作台的favorites.prepare/execute是一条直接使用链路。分类CLI还保留显式计划流程：

```powershell
uv run --no-dev bili-platform --workspace private/review plan --dataset private/review/dataset.json --results private/review/results.json --target 待归类
uv run --no-dev bili-platform --workspace private/review --cookie-file private/credentials/session.json apply --plan private/review/move-plan.json --confirm PLAN_HASH
uv run --no-dev bili-platform --workspace private/review --cookie-file private/credentials/session.json restore --plan private/review/move-plan.json --confirm PLAN_HASH
```

plan不修改B站；apply需精确计划摘要与实时账号/关系核对。恢复仅处理本地记录的实际操作，不删除用户原有目标关系，不保证恢复收藏顺序。plan-probe是隔离往返测试入口，不是内容分类结果。多目标、并发人工改动、失效视频和结果不明的写请求均不能按平台事务处理。

## 已针对的故障

| 故障 | 当前边界 |
|---|---|
| 认证、风控或异常JSON | 明确错误，不能当空结果或无字幕 |
| 分页重复或数量变化 | 不宣称完整、不猜测后续写入 |
| 请求账号、视频或分P不符 | 停止使用对应证据 |
| 字幕身份/时间异常 | 拒用；正文重复一致不证明内容正确 |
| 写请求超时 | 结果未知，先读回，不能盲目重复POST |
| 取消或服务重启 | 任务状态保留，写入不自动重放 |
| 标注与远端简介刷新 | 独立字段，人工备注不被元数据覆盖 |
| 备份异账号或损坏 | 拒绝；覆盖恢复前先保存本地备份 |
| 阅读材料变化或旧校验版本 | 缓存重新检查，旧评价不直接复用 |

自动测试采用合成账号、合成BVID、MockTransport及临时库，JS测试模拟扩展宿主。已有有界人工验证不能证明所有平台状态；本次公开准备不重新操作真实账号，也不以代码存在证明长期稳定运行。

## 可选上游机制试验

Node24+，自行取得固定BiliShelf源码后，可用合成数据运行：

```powershell
node tools/bilishelf_trial.mjs UPSTREAM_PATH .tmp/trial examples/synthetic-dataset.json
node tools/bilishelf_sync_trial.mjs UPSTREAM_PATH examples/synthetic-dataset.json .tmp/sync-result.json
```

这些试验使用上游固定版本的内部接口；生成切片须保留上游许可证。第一项生成浏览器试验页，第二项模拟远端GET，不代表运行完整上游扩展。产品启动与测试不要求安装上游工程。
